# contrib/

`contrib/` holds work prepared for other projects. It lives here so it is versioned and reviewed with the kit, but it is not part of the kit. `npm run build`, the audit, `check:ui` and the end-to-end tests don't build or check it, and it doesn't ship. Two checks do touch it: CI rebuilds each sample's `code.js` with the root TypeScript (`npx tsc -p contrib/plugin-samples/themed-resizable-window`) and fails if it differs from the committed one, and `npm test` checks that every `contrib/` folder with a `code.ts` has a `tsconfig.json` and a committed `code.js` (`test/workflows.test.mjs`) and that its Markdown links resolve. Each folder follows the conventions of the project it is for and says how to send it there. Sending it (opening a PR, for example) is always the owner's outward action. Today there is one folder: [plugin-samples/](plugin-samples/PR.md), a themed, resizable-window sample for `figma/plugin-samples`. It also holds the PR text and the owner's checklist.
